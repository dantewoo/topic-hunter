## 这是什么

Topic Hunter 是一个 Agent Skill，帮你从近几天的信息洪流里，筛出最值得做、最可能爆的选题。

**它不罗列新闻，它帮你做内容决策。**

传统选题靠经验、靠直觉、靠刷手机——Topic Hunter 把这个过程变成一套可复制的系统：

```
用户触发 → 交互（一条消息收集偏好）→ 发现（热榜脚本 + 领域搜索 + 深挖）→ 去重（本次 + 跨天）→ 时效门控 → 证据门控 → 评分（意外感+叙事力+利益钩子+热度）→ 输出（A级以上）→ 记录历史
```

---

## 为什么不一样

| 传统选题方式 | Topic Hunter |
|---|---|
| 刷一小时手机，找到5个选题 | 一次拉取 8 个热榜 + 领域搜索，输出15-20个候选 |
| "感觉这个能火" | 4维评分量化，权重按受众调整 |
| 热度全凭感觉 | 热度分必须引用榜单排名和热度值，拿不到就标“热度未验证” |
| 搜出来的都是旧闻 | 时效硬门槛，按事件日期而不是文章日期判断 |
| 同一事件搜到5遍 | 事件级去重；跨天去重，昨天推过的不再重复推 |
| 选题跟大众无关 | 强制出圈验证，圈内热度一律不认 |
| 读完不知道选哪个 | 总览表 + 切入角度 + 快速决策区 |

## 核心特性

### 4维评分体系

好选题的 DNA 不是"信息有没有价值"，而是"能不能让人停不下来"。

| 维度 | 基础权重 | 判断标准 | 案例对照 |
|---|---|---|---|
| **意外感** | 25% | 读者会不会"卧槽原来是这样"？含跨界连接、反差讽刺、身份反差、隐藏因果、反转打脸 | 潍柴成AI大赢家（AI×柴油发电机）、黄仁勋菜市场买苹果（身份反差） |
| **叙事力** | 25% | 有没有主角、冲突、赌注？能不能拍成让人看完的视频？ | 分析师肉身闯霍尔木兹（有主角有赌注） |
| **利益钩子** | 25% | 跟普通人的钱/生存/切身利益有没有直接关系？ | 量子破解比特币（钱不安全）、手机涨价（切身利益） |
| **热度** | 25% | 大众平台有没有人在讨论？出圈热才算，圈内热不算 | 微博/抖音/百度等热榜才算，Hacker News不算 |

权重按受众在基础权重上调整 5%，例如默认的“普通大众”是利益钩子 30%、热度 20%。完整权重表见 `prompts/scorer.md`。

### 6种意外感类型

意外感是选题的灵魂，我们把"卧槽原来是这样"拆解为6种可识别的模式：

1. **跨界连接** — AI×柴油发电机，地缘×中国制造
2. **反差/讽刺** — AI时代分析师反而肉身闯战区
3. **身份/地位反差** — 黄仁勋去菜市场，总统爱吃汉堡
4. **隐藏因果** — 一条推文血洗加密货币
5. **被忽视的真相** — AI搜索结果被营销操纵
6. **反转/打脸** — "永远不加广告"→加了

### 热榜脚本：热度有据可查

`scripts/fetch_hotlists.py` 一次拉取微博、百度、抖音、今日头条、知乎、B站（大众平台）和 Techmeme、Hacker News（圈内参考）的公开榜单，只用 Python 标准库，每个源只请求一次，失败就跳过。

热度评分必须引用这些信号：7 分以上要有榜单排名，热榜全部失败时热度最高 6 分并标注“热度未验证”。

### 时效门控：按内容形态区分

按“事件发生日期”判断，不是文章发布日期：

| 事件发生 | 短视频 | 图文 / 播客长视频 |
|---|---|---|
| 0-3 天前 | 通过 | 通过 |
| 4-7 天前 | 淘汰 | 有新信息、新角度的“深度跟进”可通过 |
| 7 天以上或无法判定 | 淘汰 | 淘汰 |

### 证据门控

至少 1 个官方/原始来源或 2 个独立来源；只有转载、营销号、日期不清的直接淘汰。被登录、验证码、付费墙挡住的来源只记录，不绕过。

### 去重：本次 + 跨天

同一事件被多个搜索词命中 → 合并为一条 → 记录 `hit_count`。每次推荐写入 `data/history.jsonl`，下次运行时，近 7 天推过且没有新变化的事件自动剔除，有新变化的标为“跟进”。

### 三种模式

- **发现模式**：完整流程，找今天能做的选题
- **快速模式**：跳过交互，直接用上次偏好
- **评估模式**：你给出几条新闻或热点，逐条判断能不能做、为什么

## 快速开始

### 安装

将本仓库克隆到你所用 Agent 的 skills 目录（不同平台路径不同，按实际替换）：

```bash
git clone https://github.com/dantewoo/topic-hunter.git <skills目录>/topic
```

热榜脚本需要 Python 3.8+，无第三方依赖。可以先单独跑一次确认网络可用：

```bash
python3 <skills目录>/topic/scripts/fetch_hotlists.py --limit 5
```

### 使用

在对话中说：

- **"选题"** — 一条消息选好领域/形态/受众后开始
- **"选题 科技"** — 跳过领域选择，直接按科技/AI搜索
- **"选题 快"** — 跳过交互，用上次偏好立即搜索
- **"这几条哪个能做：……"** — 评估模式
- **"第3条我做了"** — 记录到历史，之后不再重复推荐

### 个人偏好

首次交互后会生成 `.user_preferences.json`（已在 `.gitignore` 中，不会提交）。除了领域、形态、受众，还可以写个人规则，整个流程都会遵守：

```json
{
  "last_updated": "2026-10-13",
  "timezone": "Asia/Shanghai",
  "domains": ["科技/AI"],
  "content_form": "图文（公众号/小红书）",
  "audience": "普通大众/下沉市场",
  "rules": ["证据优先引用官方源和国外权威媒体"],
  "notes": "输出后问一句是否需要短视频版标题"
}
```

## 流程详解

### Phase 0：准备

确定日期和时区（默认北京时间），读取偏好文件和最近 7 天的推荐历史。

### Phase 1：交互

一条消息收集领域/内容形态/受众画像；有偏好时只问是否沿用。

### Phase 2：信息发现

1. 运行热榜脚本，拿到 8 个榜单的当前快照
2. 从热榜初筛与领域相关的条目
3. 按领域源和关键词搜索补全，优先用搜索工具的时间过滤
4. 对候选打开原始来源深挖：事件日期、关键事实、讨论量

搜索有预算上限：标准模式 30 次搜索、深挖 10 个页面，快速模式减半。

### Phase 2.5：去重

本次事件级去重 + 与历史记录跨天去重。

### Phase 3：时效门控

按事件发生日期和内容形态判断，见上文表格。

### Phase 4：证据门控

回答 5 个问题（事件日期、新变化、来源、热度信号、冲突/受限），按 strong / medium / weak 分级，weak 淘汰。

### Phase 5：评分

按受众取权重，4维打分；热度 ≤4 一票否决；“已被说烂”减 0.5；≥7.0 才能输出。

### Phase 6：输出

总览表 + Markdown 卡片 + 快速决策区（意外感最强/叙事力最强/利益钩子最直接/注意）。

### Phase 7：记录

推荐结果写入历史；用户反馈“做了/不做”也记录下来。

---

## 评分标签

| 标签 | 条件 |
|---|---|
| S级 | 总分 ≥ 8.5，现象级选题 |
| A级 | 7.0 ≤ 总分 < 8.5，优质选题 |

低于A级不输出，宁缺毋滥。评估模式例外：每条候选都会给出“推荐做 / 可以做 / 不建议”的结论。

## 适配内容形态

| 形态 | 标题风格 | 综述侧重 | 时效窗口 |
|---|---|---|---|
| 短视频 | 14字以内，强情绪钩子 | 情绪冲击和传播点 | 3 天 |
| 图文 | 不超过20字，可标题党 | 信息增量和独特角度 | 3 天，深度跟进 7 天 |
| 播客/长视频 | 不超过25字，沉稳深度 | 深度价值和讨论空间 | 3 天，深度跟进 7 天 |
