# Crawler Playbook

用于 Topic Hunter 在公开信息源上进行稳定、合规的信息发现、页面提取和失败降级。目标是提高“能取到有效证据”的概率，而不是绕过站点保护。

本文件是合规边界的唯一详细说明，其他文件只做引用。

## 合规边界

允许：
- 访问公开、无需登录、未明确禁止自动访问的页面。
- 使用搜索结果、RSS、公开接口、官方公告、公开榜单和公开讨论页。
- 使用正常浏览器渲染页面，等待动态内容加载。

禁止：
- 绕过登录、付费墙、验证码、地域封锁、账号风控或 IP 封禁。
- 使用代理池、IP 轮换、验证码识别、伪造登录态、盗用 cookie、stealth 指纹。
- 对同一站点高频、连续请求，或批量下载不必要的内容。
- 抓取或输出个人隐私、非公开数据、敏感账号信息。

遇到禁止项时，停止该源，记入 `blocked_sources`，转向公开替代来源。同一个源连续失败 2 次就放弃，不反复重试。

## 路由策略

按成本从低到高尝试：

1. 热榜脚本：`python3 scripts/fetch_hotlists.py`，一次拿到所有热榜。可用 `--sources weibo,baidu` 只拉部分源，`--format json` 拿结构化结果（含每条的链接）。
2. 搜索发现：用时间过滤或日期词、`site:`、领域词定位事件页和二级报道。
3. RSS/接口：`config/sources.json` 中 `news_feeds` 里的 Google News RSS、HN Algolia 等，适合按关键词拉按时间排序的列表。
4. 静态抓取：页面可直接抓到正文时使用。
5. 浏览器渲染：页面依赖 JavaScript 时用浏览器打开，等待主要内容出现。
6. 降级验证：正文拿不到时，用标题、摘要、榜单位置、官方公告和独立来源交叉验证。

## 查询模板

中文：
- `site:{domain} {keyword} {date}`
- `{public_keyword} {date}`
- `{cross_keyword} {year_month}`

英文：
- `site:{domain} {keyword_en} {date_en}`
- `{public_keyword_en} {date_en}`
- `{cross_keyword_en} {month_year_en}`

日期词要覆盖整个时效窗口，例如窗口是 10月11日-10月13日，就分别用“10月13日”“10月12日”“10月11日”。搜索工具支持时间范围过滤时，用过滤代替日期词。不要用“今天”“最新”“刚刚”“recent”。

## 浏览器提取

适合热榜脚本失败的热榜页、动态列表、懒加载正文。

步骤：
1. 打开页面后等待主要容器、榜单项或正文节点出现。
2. 先提取结构化信息：标题、热度值、排名、链接、发布时间、作者/来源。
3. 滚动只做必要范围，不要无限滚动。榜单页取前 30 条即可。
4. 记录可验证的 URL 和抓取时间。

失败处理：
- 空页面：等待一次后刷新，仍失败则降级。
- 需要登录或验证码：停止该源，记录“登录/验证码受限”。
- 内容缺失：用搜索结果、RSS 或其他媒体源补证。

## 正文提取

每篇正文至少抽取：
- 标题、URL、来源/作者、发布时间
- 事件发生日期
- 关键事实 1-3 条
- 讨论量或热度信号
- 指向原始来源的链接

事件日期判定顺序：
1. 官方公告或原始发布的日期
2. 文中明确写出的事件发生日期
3. 多家媒体一致报道的发生日期
4. 只有文章发布日期时，不足以证明事件日期，要找其他来源确认

海外事件按当地日期发生的，换算到偏好时区（默认北京时间）后再计算 days_ago。

## 反阻断降级树

当目标源无法直接抓取：

1. 查官方公告、原始帖子、公司博客、监管文件、平台公告。
2. 查 Google News RSS、Techmeme、HN Algolia、Reddit 搜索等公开索引。
3. 查同一事件的独立媒体报道。
4. 查搜索结果摘要和热榜页，只用于发现，不单独作为强证据。
5. 仍无法验证事件日期或核心事实，淘汰候选。

不要为了某个源强行突破访问限制。选题系统需要的是可靠证据，不是拿到每一个页面。
